The SmartTask Planner follows the standard Three-Tier Client-Server Architecture using the RESTful API pattern. It splits the whole application into 3 clean, independent layers:

Justification (Why did we choose this architecture?)

Here are 5 simple reasons to explain why 3-tier architecture is best for this student project:

1. Separation of Work (Modularity)

The frontend team can easily design UI screens in React without worrying about database queries. The backend handles business calculations (e.g. scheduling slots) independently.

2. Easy to Maintain & Debug

If we change a button color or calendar UI in React, the backend doesn't crash. If we update a task priority algorithm in Express, the frontend code remains untouched.

3. Stateless Scalability with JWT

Instead of storing login sessions on the server, we use JSON Web Tokens. Each request carries the token, meaning the server doesn't waste RAM keeping millions of session cookies.

4. MongoDB Document Flexibility

Academic tasks have varied fields: subtasks list, tags, duration, and priority. MongoDB stores them naturally as JSON/BSON documents without complex multi-table SQL joins.

Viva Summary: "Our project uses a 3-tier client-server architecture with React for Tier 1 (Presentation), Express & Node.js for Tier 2 (Application logic), and MongoDB for Tier 3 (Database), connected securely via RESTful APIs and JWT tokens."
